# 历史保存与 Recorder 安全边界

只读源码审查基线：Fork main `372b0b2`。本次未访问或修改用户 HA 数据库、配置、实体注册表或已有统计。

## 已确认的风险

- 批量历史抓取未设置 timestamp，后续清理把缺少时间的账单视为过期；每次刷新使用不同存储实例，还可能覆盖并发写入。
- 累计费用把已保存账单与当前预估相加，同一张已出账单可能重复计费。截断、过期清理或加载失败又可能让累计值回退。
- 旧启动逻辑直接修改 SQLite：将短期 sum 强制设为绝对表读数，先删除再插入历史统计；费用路径在“仅补缺失”模式下也会重写。绝对表底不能视作新消耗，这些路径有制造异常用量的风险。
- 接口失败、数字缺失与真实零值被混用；年度缴费计数只取第一页，上期用量取错年度图表位置。
- Token 刷新 DEBUG 记录整个响应，可能泄露凭据。

## 本次安全替代方案

1. 移除本集成所有主动 Recorder 注入、原生 SQL 和启动/延时统计“修复”，包括刷新时的增量注入。本地历史抓取只保存账单，不再声称导入能源统计。不新增能源实体、模板或仪表盘。
2. 已有长期、短期统计及其元数据原样保留，不迁移、不删除、不回填。HA 继续按现有实体状态自行记录；既有异常不会被本补丁自动消除。
3. 继续使用相同 HA Store key、版本和账单字段，改用官方 `Store.async_save` 的原子保存；同一配置条目共用存储和写锁。账单不按观察 timestamp 过期，旧的无 timestamp 记录也保留。
4. 累计费用只合计已出账费用，每张账单去重，预估仍独立展示。保存已确认合计的基线；缺字段、加载/保存失败、合计异常降低时不给出猜测金额，也不以零覆盖有效累计读数。
5. 账期不等于自然月。上期用量来自上一账期；图表按出账月读取，null 保持未知。上年度均值仅在十二个月数据完整时计算，并标注口径。
6. 不更改任何现有 unique_id，不调用实体注册表迁移 API，不修改用户配置。

## 兼容性与用户手动事项

- HA 2026.10 中 monetary 的统计 state_class 仅支持 TOTAL，货币单位使用 CNY。按次账单、余额、历史均值、预测等不冒充累计计数器；这些实体以后不主动生成错误的增长统计，原有统计保留。
- HA 官方统计导入 API 要求显式 mean_type 和 unit_class（2026.11 强制）。本补丁删除全部导入调用，因此不依赖这些已弃用的省略参数，也不再直接依赖数据库表结构。
- 请在升级前使用 HA 官方备份保存配置、`.storage` 与一致性 Recorder 数据。部署后按自己的独立模板配置能源和成本来源。
- 已存在的虚假尖峰、旧货币单位或旧统计基线，需要你在 HA 统计页面先只读核对，再自行决定是否用 HA 官方工具处理。本补丁不自动修复这些数据，也不影响其他集成。
- 如本地账单曾被旧版清理，可手动使用原“抓取历史记录”按钮重新抓取；无法从接口恢复的记录不会猜测重建。明确的官方账单金额下调也可能触发基线保护，应先核对账单；不要手改累计值消除提示。
- 回滚代码不需要数据库回滚；已保留的旧账单及新增存储元数据保持同一版本兼容。不要重新启用旧版本的自动统计删写逻辑。
